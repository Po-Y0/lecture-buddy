# Project Proposal — Lecture Buddy

## 1. Theme

**Tools for Modern Learners**

ทีมเลือก Theme นี้เนื่องจาก Lecture Buddy มีเป้าหมายในการช่วยนักศึกษาจัดการและทบทวนเนื้อหาจากการเรียนอย่างเป็นระบบ โดยเน้นลดภาระในการจัดเก็บและค้นหาเนื้อหาที่เกี่ยวข้องกับแต่ละรายวิชา และช่วยให้นักศึกษาสามารถทบทวนบทเรียนได้สะดวกมากขึ้น

## 2. Project Name

**Lecture Buddy**

Lecture Buddy is a web application designed to support university students in managing, organizing, and reviewing lecture materials in one place.

## 3. Primary Persona

**University Student**

นักศึกษาระดับมหาวิทยาลัยที่ต้องเรียนหลายรายวิชาและมีเนื้อหาจำนวนมากจากการเรียน เช่น lecture notes, เอกสารประกอบการเรียน และงานที่เกี่ยวข้องกับแต่ละวิชา ผู้ใช้ต้องการจัดระเบียบเนื้อหาให้ค้นหาได้ง่ายและสามารถกลับมาทบทวนบทเรียนได้โดยไม่ต้องเสียเวลาในการค้นหาข้อมูลจากหลายแหล่ง

## 4. Value Proposition

Lecture Buddy ช่วยแก้ปัญหาการจัดการเนื้อหาการเรียนที่กระจัดกระจายและการค้นหาเนื้อหาที่ใช้เวลานาน โดยรวบรวมและจัดระเบียบข้อมูลการเรียนไว้ในระบบเดียว

ผู้ใช้สามารถเข้าถึงเนื้อหาและทบทวนบทเรียนได้สะดวกขึ้น ช่วยลดเวลาในการจัดการข้อมูลและสนับสนุนการเรียนรู้ด้วยตนเอง

## 5. MoSCoW Priorities

### Must Have

1. **จัดการรายวิชา** — ผู้ใช้สามารถสร้างและดูรายวิชาที่กำลังเรียนได้
2. **จัดการ Lecture** — ผู้ใช้สามารถเพิ่มและดูเนื้อหา Lecture ของแต่ละรายวิชาได้
3. **ค้นหาเนื้อหา** — ผู้ใช้สามารถค้นหา Lecture หรือเนื้อหาที่ต้องการได้
4. **จัดระเบียบเนื้อหาตามรายวิชา** — เนื้อหาต้องถูกจัดกลุ่มตามรายวิชาอย่างชัดเจน

### Should Have

5. **สรุปเนื้อหาด้วย AI** — ผู้ใช้สามารถสร้างสรุปจากเนื้อหา Lecture เพื่อช่วยทบทวนได้
6. **สร้างคำถามทบทวน** — ระบบสามารถช่วยสร้างคำถามจากเนื้อหา Lecture เพื่อใช้ในการทบทวน

### Could Have

7. **ระบบติดตามความก้าวหน้าในการทบทวน** — ผู้ใช้สามารถดูความคืบหน้าของการทบทวนแต่ละรายวิชาได้

### Won't Have This Term

8. **ระบบทำงานร่วมกันแบบ Real-time ระหว่างนักศึกษาหลายคน** — ยังไม่อยู่ในขอบเขตของ Sprint/ภาคการศึกษานี้

## 6. Risks & Assumptions

### Assumptions

* นักศึกษามี Lecture materials ที่สามารถนำเข้าสู่ระบบได้
* นักศึกษาต้องการรวบรวมเนื้อหาการเรียนไว้ในระบบเดียว
* ผู้ใช้สามารถใช้งานเว็บแอปผ่านอุปกรณ์ที่เชื่อมต่ออินเทอร์เน็ตได้

### Risks

* เนื้อหา Lecture อาจมีรูปแบบไฟล์หรือโครงสร้างที่หลากหลาย ทำให้การประมวลผลข้อมูลทำได้ยาก
* การสรุปเนื้อหาด้วย AI อาจมีข้อมูลคลาดเคลื่อนจากเนื้อหาต้นฉบับ จึงจำเป็นต้องให้ผู้ใช้สามารถตรวจสอบข้อมูลได้
* ขอบเขตของฟีเจอร์ AI อาจมีความซับซ้อนและใช้เวลาพัฒนามากกว่าที่คาดการณ์

## Definition of Done

A feature is considered Done when:

* มีการพัฒนาและทดสอบฟังก์ชันตาม Acceptance Criteria ครบถ้วน
* โค้ดผ่านการตรวจสอบโดยสมาชิกทีมอย่างน้อย 1 คน
* มีการทดสอบฟังก์ชันหลักและไม่พบข้อผิดพลาดที่กระทบต่อการใช้งานหลัก
* UI สามารถใช้งานได้ตาม User Story
* Pull Request ผ่านการ Review ก่อน Merge
* Issue ที่เกี่ยวข้องได้รับการอัปเดตและปิดเมื่อทำงานเสร็จ
